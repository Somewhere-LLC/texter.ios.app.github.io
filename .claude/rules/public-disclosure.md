# 公開情報に内部情報を載せない

2026-11-05 ユーザー指示。このリポジトリは公開されている。サイトの文、コミットメッセージ、PRのタイトル・本文・コメント、ブランチ名は、誰でも読める。内部の情報や、弱点の手がかりになる情報は、これらに書かない。

## 載せないもの

1. 基盤サービスの固有名。音声認識、AI、課金、広告、認証、解析、クラウドの事業者名と製品名が対象。利用規約など、法的に必要な既存の記載は除く。利用者向けの説明は「クラウドの音声認識」のように、一般名で書く
2. 内部の構成。通信先、サーバーの設定名とフラグ名、関数名、プロジェクトID、バケット名、アカウント名、非公開リポジトリのファイルパス、内部の処理の細かい条件
3. 秘密情報。鍵、トークン、認証情報
4. 弱点の手がかり。未修正の不具合、防御の抜け、回避の方法、検査のすり抜け方。検証中に見つけた弱点は、公開の場所に書かず、ユーザーへ直接報告する
5. 運用の内部情報。公開前の機能の予定、段階公開の割合、承認待ちの事情

## 代わりにどう書くか

- 利用者が判断に使う挙動は書いてよい。例は、音声が端末内で処理されるか、クラウドへ送られるか。名前や条件の細部は書かず、「クラウドの音声認識へ送る」のような一般名で書く
- コードを調べて得た根拠は、会話でユーザーに伝える。公開の場所には「コードで確認した」までにとどめ、ファイル名や設定名は書かない
- 確認していないことは、確認していないと書く。内部の事情を理由として書かない

## 強制の仕組み

| 場面 | 仕組み | 結果 |
|---|---|---|
| Claude Code が `git commit`、`gh pr`・`gh issue` の書き込み、コメントの投稿をするとき | `.claude/hooks/disclosure-gate.py`（PreToolUse、`.claude/settings.json`） | 本文に該当があれば止める |
| コミットするとき | `.githooks/pre-commit`（差分の追加行）と `.githooks/commit-msg`（メッセージ） | 該当があればコミットを止める |
| ビルドするとき | `npm run build` の中の `--tree`（追跡中のファイル全体） | 該当があれば失敗する |

- 事業者名と内部の識別子は、ハッシュで `.claude/hooks/disclosure-data.json` に入れる。名前そのものを、このリポジトリに載せないため。足すときは `python3 .claude/hooks/disclosure-gate.py --add-token <語>` を使う
- 法的に必要な既存の記載だけは、`--add-baseline <パス> <語>` で許可する。許可は、承認した行の内容に結び付く。同じ語を同じファイルの別の行に足せば、止まる。許可はPRで人が承認する（`.claude/hooks/` の変更は自律マージの対象外）
- 名前の一覧のファイルが読めないときは、検査を通さず止める
- 判定の対象外にできるのは、このルールと検査スクリプトだけ。ほかのファイルを対象外にしない
- 検査にかからない言い回しで書いても、ルールを守ったことにならない。迷ったら書かない

## 混入したとき

1. push する前なら、コミットを作り直す。履歴に残さない
2. push 済みなら、force push は使えない。`main` から作り直した別名のブランチに、1コミットで出し直す。古いPRを閉じ、古いブランチを削除する
3. 閉じたPRのコミットは、GitHub に残る。SHA を指定すれば読めるので、完全に消すには GitHub サポートへの依頼が要る。ユーザーに、混入した内容と、この限界を伝える
